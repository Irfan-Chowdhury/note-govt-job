## Q1. Briefly describe the relationship among threat, vulnerability and attack.

Cyber Security-তে **Threat, Vulnerability এবং Attack** একে অপরের সঙ্গে সম্পর্কিত তিনটি গুরুত্বপূর্ণ বিষয়।

### ১. Threat (হুমকি)
Threat হলো এমন কোনো সম্ভাব্য বিপদ, ব্যক্তি বা ঘটনা, যা কম্পিউটার সিস্টেম, নেটওয়ার্ক বা ডেটার ক্ষতি করতে পারে।

**উদাহরণ:** একজন Hacker কোনো Website থেকে গ্রাহকদের ব্যক্তিগত তথ্য চুরি করতে চায়। এখানে Hacker-এর আক্রমণের উদ্দেশ্য একটি সম্ভাব্য Threat।

### ২. Vulnerability (দুর্বলতা)
Vulnerability হলো কোনো সিস্টেম, সফটওয়্যার বা নেটওয়ার্কের নিরাপত্তাগত দুর্বলতা, যা কাজে লাগিয়ে আক্রমণকারী ক্ষতি করতে পারে।

**উদাহরণ:** একটি Website-এর কোডে SQL Injection-এর দুর্বলতা রয়েছে। আক্রমণকারী এই দুর্বলতা কাজে লাগিয়ে Database-এ অননুমোদিত প্রবেশের চেষ্টা করতে পারে।

### ৩. Attack (আক্রমণ)
Attack হলো কোনো সিস্টেমের নিরাপত্তা দুর্বলতা কাজে লাগিয়ে ক্ষতি করা, তথ্য চুরি করা বা অননুমোদিত প্রবেশের চেষ্টা করা।

**উদাহরণ:** একজন Hacker SQL Injection ব্যবহার করে Website-এর Database থেকে তথ্য চুরি করার চেষ্টা করে। এটি একটি Cyber Attack।

### তিনটির মধ্যে সম্পর্ক

ধরো, একটি অনলাইন ব্যাংকিং Website-এর Database-এ গ্রাহকদের গুরুত্বপূর্ণ তথ্য রয়েছে।

- **Threat:** একজন Hacker গ্রাহকদের তথ্য চুরি করতে চায়।
- **Vulnerability:** Website-এর কোডে SQL Injection-এর দুর্বলতা রয়েছে।
- **Attack:** Hacker সেই দুর্বলতা কাজে লাগিয়ে Database-এ প্রবেশের চেষ্টা করে।

**সুতরাং, Threat হলো সম্ভাব্য বিপদ, Vulnerability হলো সিস্টেমের দুর্বলতা এবং Attack হলো সেই দুর্বলতা কাজে লাগিয়ে আক্রমণের চেষ্টা।** সফল Attack-এর ফলে ডেটা চুরি, আর্থিক ক্ষতি বা সিস্টেমের কার্যক্রম ব্যাহত হতে পারে।

মনে রাখবে, Threat থাকলেই Attack ঘটবে এমন নয়, আর Vulnerability থাকলেই তা অবশ্যই কাজে লাগানো হবে এমনও নয়। তবে Threat কোনো Vulnerability কাজে লাগিয়ে Attack করলে সিস্টেমের ক্ষতি হওয়ার ঝুঁকি তৈরি হয়।

## ১. SQL Injection কী? কীভাবে prevent করা যায়? **[BTV(AP)-2019]**

### সংজ্ঞা
**SQL Injection (SQLi)** হলো একটি web application attack, যেখানে attacker input field (login form, search box, URL) এর মাধ্যমে **malicious SQL code** ঢুকিয়ে দেয়, ফলে database-এর query বদলে যায়। এতে attacker অনুমতি ছাড়াই data দেখতে, বদলাতে বা delete করতে পারে।

### কীভাবে কাজ করে (Diagram)

```
Attacker ──► Input Field ──► Web App ──► Database
 (' OR '1'='1)   (validation নেই)   (query তৈরি)   (সব data ফেরত দেয়)
                                          │
                                          ▼
                          Attacker পেয়ে যায় unauthorized data
```

### Example
Login query:
```sql
SELECT * FROM users WHERE username='$u' AND password='$p';
```
Attacker username-এ দিল: `admin' --`  অথবা password-এ: `' OR '1'='1`

Query হয়ে যায়:
```sql
SELECT * FROM users WHERE username='admin' AND password='' OR '1'='1';
```
`'1'='1'` সবসময় **true**, তাই password ছাড়াই login হয়ে যায়।

### প্রকারভেদ
| Type | কাজ |
|---|---|
| **In-band** (Error-based, Union-based) | একই channel দিয়ে attack ও result পায় |
| **Blind** (Boolean-based, Time-based) | সরাসরি result দেখে না, true/false বা delay দেখে অনুমান করে |
| **Out-of-band** | অন্য channel (DNS/HTTP) দিয়ে data বের করে |

### Prevention (প্রতিরোধ)
1. **Prepared Statement / Parameterized Query** ব্যবহার করা (সবচেয়ে কার্যকর)
2. **Stored Procedure** ব্যবহার করা
3. **Input Validation ও Sanitization** (whitelist, special character `' " ; --` escape করা)
4. **Least Privilege**: database user-কে শুধু দরকারি permission দেওয়া (admin/root দিয়ে app না চালানো)
5. **Error message hide করা**: user-কে database error না দেখানো
6. **Web Application Firewall (WAF)** ব্যবহার করা
7. **ORM** ব্যবহার করা এবং software নিয়মিত **update/patch** করা

Safe code example:
```sql
SELECT * FROM users WHERE username = ? AND password = ?;
-- ? এর মান আলাদাভাবে bind হয়, code হিসেবে execute হয় না
```

### 📌 মনে রাখার মতো তথ্য
- SQLi, **OWASP Top 10**-এর **Injection** category-র অন্তর্গত।
- SQLi আক্রমণ করে **Database layer**-কে, আর **XSS** আক্রমণ করে **user-এর browser**-কে।
- সবচেয়ে ভালো প্রতিরোধ: **Parameterized Query**।
- Attack-এর কারণ: user input-কে **trust করে সরাসরি query-তে বসানো**।
- SQLi **CIA Triad**-এর Confidentiality, Integrity, Availability সবকিছুকেই হুমকিতে ফেলে।
- Comment symbol: `--` (MySQL/SQL Server), `#` (MySQL), যা query-র বাকি অংশ বাদ দিতে ব্যবহৃত হয়।

### 🎯 পরীক্ষার টিপস
- Written-এ **সংজ্ঞা → example query → prevention (৪-৫ পয়েন্ট)** এই ক্রমে লিখুন।
- `' OR '1'='1` example লিখলে ভালো নম্বর পাওয়া যায়।
- MCQ-তে "সবচেয়ে ভালো প্রতিরোধ" এলে উত্তর **Prepared Statement/Parameterized Query**।

## ২. Internet-এর মাধ্যমে বিভিন্ন Attack-এর নাম **[HBFC & KB(AP)-2018]**

### Attack-এর শ্রেণিবিন্যাস (Diagram)

```
                    Internet Attacks
                          │
   ┌──────────┬───────────┼────────────┬─────────────┐
 Malware   Network     Web-based    Social/       Password
  based    based        attacks    Identity       attacks
   │          │            │          │              │
 Virus     DoS/DDoS     SQL Inj.   Phishing      Brute Force
 Worm      MITM          XSS        Pharming      Dictionary
 Trojan    Sniffing     CSRF       Spoofing
 Ransomware Spoofing    Session    Social Eng.
 Spyware               Hijacking
```

### প্রধান Attack-এর তালিকা

| Attack | সংক্ষিপ্ত ব্যাখ্যা |
|---|---|
| **Virus** | অন্য file/program-এর সাথে যুক্ত হয়ে ছড়ায়, host লাগে |
| **Worm** | নিজে নিজেই network দিয়ে copy হয়ে ছড়ায়, host লাগে না |
| **Trojan Horse** | ভালো software-এর ছদ্মবেশে থাকা malware, backdoor খুলে দেয় |
| **Ransomware** | data encrypt করে মুক্তিপণ (ransom) চায় (যেমন: WannaCry) |
| **Spyware / Keylogger** | গোপনে user-এর কার্যকলাপ ও keystroke record করে |
| **Phishing** | ভুয়া email/website দিয়ে password, card info চুরি |
| **Pharming** | DNS বদলে user-কে ভুয়া site-এ পাঠানো |
| **DoS / DDoS** | অতিরিক্ত request পাঠিয়ে server অচল করা (DDoS-এ অনেক computer/**botnet**) |
| **Man-in-the-Middle (MITM)** | দুই পক্ষের communication-এর মাঝে ঢুকে আড়ি পাতা/বদলানো |
| **SQL Injection** | input-এ malicious SQL ঢুকিয়ে database হ্যাক |
| **XSS (Cross-Site Scripting)** | web page-এ malicious script ঢুকিয়ে user-এর browser-এ চালানো |
| **CSRF** | logged-in user-কে দিয়ে অনিচ্ছাকৃত request করানো |
| **Spoofing** | IP/Email/DNS-এর ভুয়া পরিচয় ব্যবহার |
| **Sniffing** | network packet ধরে data পড়া |
| **Brute Force / Dictionary** | সম্ভাব্য সব/প্রচলিত password একে একে চেষ্টা |
| **Session Hijacking** | user-এর active session চুরি করে login-এর মতো আচরণ |
| **Social Engineering** | মানুষকে ধোঁকা দিয়ে গোপন তথ্য বের করা |
| **Zero-day Attack** | যে দুর্বলতার patch এখনো নেই, তার ওপর আক্রমণ |
| **Logic Bomb** | নির্দিষ্ট শর্তে (তারিখ/ঘটনা) সক্রিয় হওয়া malicious code |

### 📌 মনে রাখার মতো তথ্য
- **Virus vs Worm**: Virus-এর **host/user action** লাগে; Worm **নিজে নিজেই** ছড়ায়।
- **DoS vs DDoS**: DoS = একটি source থেকে; DDoS = **অনেক source (botnet)** থেকে।
- **Phishing vs Pharming**: Phishing-এ user-কে **প্রলুব্ধ** করা হয়; Pharming-এ **DNS বদলে** জোর করে ভুয়া site-এ নেওয়া হয়।
- **Smishing** = SMS দিয়ে phishing; **Vishing** = voice call দিয়ে phishing।
- **Trojan** নিজে ছড়ায় না, user নিজেই install করে।
- **Ransomware**-এর বিখ্যাত উদাহরণ: **WannaCry (2017)**।
- **Botnet** = hacker-নিয়ন্ত্রিত infected computer-এর নেটওয়ার্ক (zombie computers)।

### 🎯 পরীক্ষার টিপস
- Written-এ কমপক্ষে **৮-১০টি** attack নাম ও এক লাইনের ব্যাখ্যা লিখুন; category অনুযায়ী সাজালে ভালো দেখায়।
- MCQ-তে সবচেয়ে বেশি আসে **তুলনামূলক প্রশ্ন** (Virus vs Worm, DoS vs DDoS, Phishing vs Pharming) এবং **"কোনটি malware নয়?"** ধরনের প্রশ্ন। (উত্তর: Phishing, DDoS, SQLi ইত্যাদি malware নয়, এগুলো attack technique।)

## Q2 & Q3 : Preserving Confidentiality, Integrity and availability of data is a restatement of the concern over falsification, interception, masquerade and denial-of-service. Explain how do the first three concepts relate to the last four. [BB-AP-2023]

## 📘 Handnote: CIA Triad ও Security Threats-এর সম্পর্ক

## প্রশ্নের মূল কথা
**Confidentiality, Integrity, Availability (CIA)** হলো security-র তিনটি **লক্ষ্য**। আর **Interception, Falsification, Masquerade, DoS** হলো সেই লক্ষ্য ভাঙার চারটি **হুমকি (threat)**। অর্থাৎ CIA রক্ষা করা মানেই এই চার হুমকি ঠেকানো।

## সংজ্ঞা

| Concept | মানে |
|---|---|
| **Confidentiality** | শুধু authorized ব্যক্তিই data দেখতে পাবে |
| **Integrity** | data অনুমতি ছাড়া বদলানো যাবে না, সঠিক ও অপরিবর্তিত থাকবে |
| **Availability** | বৈধ user দরকারের সময় system/data পাবে |
| **Interception** | অননুমোদিত পক্ষ data আড়ি পেতে দেখে ফেলা |
| **Falsification (Modification)** | data বদলে ফেলা বা নকল তথ্য ঢোকানো |
| **Masquerade** | অন্যের ছদ্মবেশে (fake identity) system-এ ঢোকা |
| **Denial of Service** | system-কে অচল করে বৈধ user-কে সেবা থেকে বঞ্চিত করা |

## সম্পর্ক (Diagram)

```
   Security Goal (CIA)              Threat (যা goal ভাঙে)
 ┌────────────────────┐
 │ Confidentiality    │◄──────── Interception
 │ (গোপনীয়তা)          │◄─ ─ ─ ─ Masquerade (আংশিক)
 ├────────────────────┤
 │ Integrity          │◄──────── Falsification
 │ (অখণ্ডতা)            │◄─ ─ ─ ─ Masquerade (fake data/identity)
 ├────────────────────┤
 │ Availability       │◄──────── Denial of Service
 │ (প্রাপ্যতা)           │
 └────────────────────┘
```

## ব্যাখ্যা

| CIA | সম্পর্কিত Threat | কেন |
|---|---|---|
| **Confidentiality** | **Interception** | আড়ি পেতে data দেখলেই গোপনীয়তা নষ্ট হয় |
| **Integrity** | **Falsification** | data বদলালে বা নকল data ঢোকালে অখণ্ডতা নষ্ট হয় |
| **Availability** | **Denial of Service** | সেবা বন্ধ হলে data/system পাওয়া যায় না |
| **Confidentiality + Integrity** | **Masquerade** | ভুয়া পরিচয়ে ঢুকে data দেখে (C) এবং বদলাতে পারে (I) |

**Masquerade** সরাসরি একটি goal ভাঙে না, এটি **authentication ব্যর্থ হওয়ার** ফল। এর মাধ্যমেই attacker পরে interception বা falsification ঘটায়।

## Real Scenario
**একটি ব্যাংকের online system:**
1. Attacker public Wi-Fi-তে নেটওয়ার্ক sniff করে customer-এর transaction দেখল → **Interception** (Confidentiality নষ্ট)
2. Attacker customer-এর password দিয়ে login করে নিজেকে customer দাবি করল → **Masquerade**
3. সে transfer-এর account number বদলে নিজের account বসাল → **Falsification** (Integrity নষ্ট)
4. শেষে হাজার হাজার fake request পাঠিয়ে server অচল করল → **DoS** (Availability নষ্ট)

## প্রতিরোধ (সংক্ষেপে)

| Threat | সমাধান |
|---|---|
| Interception | **Encryption** (HTTPS/TLS) |
| Falsification | **Hash, Digital Signature, Checksum** |
| Masquerade | **Authentication** (password, OTP, 2FA) |
| DoS | **Firewall, Load Balancer, Rate Limiting, Redundancy** |

## Laravel Reference
```php
Hash::make($password);                        // Integrity/password সুরক্ষা
Crypt::encryptString($data);                  // Confidentiality
Route::middleware('throttle:60,1');           // DoS প্রতিরোধ (rate limiting)
Route::middleware('auth');                    // Masquerade প্রতিরোধ (authentication)
```
`@csrf` token ও HTTPS ব্যবহার করলে falsification ও interception-এর ঝুঁকি কমে।

## 📌 মনে রাখার মতো তথ্য
- **CIA = Confidentiality, Integrity, Availability**
- Interception → **Confidentiality**, Falsification/Modification → **Integrity**, DoS/Interruption → **Availability**
- Interception হলো **passive attack** (শুধু দেখে); Falsification, Masquerade, DoS হলো **active attack** (কিছু বদলায়/ক্ষতি করে)।
- Masquerade-এর বিপরীতে প্রয়োজন **Authentication**; অস্বীকার ঠেকাতে লাগে **Non-repudiation**।
- Classic চার threat: **Interception, Interruption, Modification, Fabrication**। Masquerade হলো Fabrication-এরই একটি রূপ।
- Confidentiality-র প্রধান হাতিয়ার **Encryption**; Integrity-র **Hashing**; Availability-র **Backup ও Redundancy**।

## 🎯 পরীক্ষার টিপস
- Written-এ **একটি table (CIA ↔ Threat)** আর একটি ছোট scenario লিখলে পূর্ণ নম্বর পাওয়া সহজ।
- Masquerade কোন goal-এ পড়ে সেটা প্রশ্ন হলে লিখুন: *"Authentication ব্যর্থতা, যা Confidentiality ও Integrity দুটোকেই ঝুঁকিতে ফেলে।"*
- MCQ-তে মনে রাখুন: **Interception = Confidentiality, Falsification = Integrity, DoS = Availability।**

# Q4 : Describe how the principles of Confidentiality, Integrity, and Availability (CIA Triad) work together to protect organizational data, and provide one real-world example of a security breach where one or more principles were compromised.


প্রশ্নটার অর্ধেক আগের উত্তরে ছিল (CIA-র সংজ্ঞা, ব্যাংকের scenario)। কিন্তু **"তিনটি principle একসাথে কীভাবে কাজ করে"** আর **"real-world breach example"** অংশ দুটো আগে ছিল না। তাই এই প্রশ্নের পূর্ণ উত্তর নিচে দিলাম।

## 📘 Handnote: CIA Triad একসাথে কীভাবে Data রক্ষা করে + Real Breach Example

## ১. তিনটি Principle একসাথে কীভাবে কাজ করে

তিনটি আলাদা দেয়াল নয়, বরং **একটি অন্যটির ওপর নির্ভরশীল**। একটি ভাঙলে বাকি দুটিও দুর্বল হয়ে পড়ে।

```
        ┌─────────────────────────────────┐
        │   Organizational Data           │
        │                                 │
        │  C ──► কে দেখবে (Access Control, Encryption)
        │  I ──► কী অবস্থায় থাকবে (Hash, Signature)
        │  A ──► কখন পাবে (Backup, Redundancy)
        └─────────────────────────────────┘
        তিনটি মিলেই data "নিরাপদ ও ব্যবহারযোগ্য"
```

| সম্পর্ক | ব্যাখ্যা |
|---|---|
| **C + I** | Data গোপন থাকলেও কেউ বদলে ফেললে লাভ নেই। আবার ঠিক থাকলেও সবাই দেখে ফেললে লাভ নেই। |
| **C + A** | অতিরিক্ত কড়াকড়ি (Confidentiality) করলে বৈধ user-ই data পায় না (Availability কমে)। |
| **I + A** | Data নষ্ট বা ভুল হলে সেটা পাওয়া গেলেও কাজে লাগে না। |
| **Trade-off** | তিনটির মধ্যে **ভারসাম্য** রাখাই security design-এর মূল চ্যালেঞ্জ। |

**একসাথে কাজের উদাহরণ (ব্যাংকের লেনদেন):**
Customer login করলে **OTP** লাগে (C), transaction-এর amount **hash দিয়ে যাচাই** হয় (I), আর server বন্ধ হলে **backup server** সেবা চালু রাখে (A)।

## ২. Real-World Breach Example: Bangladesh Bank Heist (2016)

| বিষয় | তথ্য |
|---|---|
| **ঘটনা** | Hacker-রা Bangladesh Bank-এর **SWIFT** system-এ ঢুকে Federal Reserve Bank of New York-এর কাছে জাল payment instruction পাঠায় |
| **পরিমাণ** | প্রায় **১০১ মিলিয়ন ডলার** চাওয়া হয়, প্রায় **৮১ মিলিয়ন ডলার** ফিলিপাইনে চলে যায় |
| **কারণ** | Malware ও চুরি করা credential, দুর্বল network security |

**কোন Principle ভেঙেছে:**

| Principle | কীভাবে ভাঙল |
|---|---|
| **Confidentiality** | SWIFT credential হ্যাকারদের হাতে চলে যায় |
| **Integrity** | জাল payment message পাঠানো হয়, এবং log/record-এর সাথে কারসাজি হয় |
| **Availability** | Printer ও সংশ্লিষ্ট system অচল থাকায় confirmation দেরিতে পাওয়া যায় |

**শিক্ষা:** শক্তিশালী firewall, network segmentation, 2FA, ও monitoring থাকলে ঠেকানো সম্ভব হতো।

### বিকল্প Example (প্রয়োজনে লিখতে পারেন)

| Breach | ভাঙা Principle |
|---|---|
| **Equifax (2017):** আনুমানিক ১৪.৭ কোটি মানুষের তথ্য ফাঁস, patch না করার কারণে | **Confidentiality** |
| **WannaCry (2017):** Ransomware, NHS সহ বহু দেশের system অচল | **Availability** (সাথে Integrity) |

## Laravel Reference

```php
hash_hmac('sha256', $data, $key);              // Integrity যাচাই
// Queue + DB backup + load balancer            // Availability
```

## 📌 মনে রাখার মতো তথ্য
- তিনটি principle **পরস্পর নির্ভরশীল**, একটি ভাঙলে বাকি দুটি ঝুঁকিতে পড়ে।
- **Trade-off:** Confidentiality বাড়ালে Availability কমতে পারে।
- Bangladesh Bank heist: **২০১৬**, **SWIFT**, প্রায় **$৮১ মিলিয়ন** চুরি।
- Equifax breach-এর মূল কারণ ছিল **unpatched vulnerability**।
- WannaCry **Availability** আক্রমণের বিখ্যাত উদাহরণ।

# Q5: What are hackers who find bugs and vulnerabilities called? Write down the definition of White hat, Black hat and gray hat hackers.

## 📘 Handnote: Hacker-এর ধরন (White, Black, Gray Hat)

## প্রশ্নের উত্তর: Bug ও Vulnerability খুঁজে বের করা hacker-দের কী বলে?

এদের বলা হয় **Ethical Hacker** বা **White Hat Hacker**। এরা অনুমতি নিয়ে system-এর দুর্বলতা খুঁজে বের করে এবং মালিককে জানায়, যাতে ক্ষতি হওয়ার আগেই ঠিক করা যায়। এদের **Security Researcher** বা **Bug Bounty Hunter**ও বলা হয়।

## Hacker-এর মূল তিন ধরন (Diagram)

```
        অনুমতি আছে?          উদ্দেশ্য
 ┌──────────────────────────────────────────┐
 │ White Hat  │  ✅ হ্যাঁ     │ নিরাপত্তা বাড়ানো   │
 │ Gray Hat   │  ❌ না        │ ভালো উদ্দেশ্যে, কিন্তু আইন ভাঙে │
 │ Black Hat  │  ❌ না        │ ক্ষতি / আর্থিক লাভ   │
 └──────────────────────────────────────────┘

   White ◄────────── Gray ──────────► Black
  (সম্পূর্ণ বৈধ)   (মাঝামাঝি)       (সম্পূর্ণ অবৈধ)
```

## সংজ্ঞা

| ধরন | সংজ্ঞা | কাজ |
|---|---|---|
| **White Hat** (Ethical Hacker) | যারা মালিকের **লিখিত অনুমতি নিয়ে** system-এর দুর্বলতা খুঁজে বের করে ও ঠিক করতে সাহায্য করে | Penetration Testing, Vulnerability Assessment, Bug Bounty |
| **Black Hat** (Cracker) | যারা **অনুমতি ছাড়া, খারাপ উদ্দেশ্যে** (চুরি, ক্ষতি, মুক্তিপণ) system ভেঙে ঢোকে | Data চুরি, Ransomware, Malware ছড়ানো, Bank fraud |
| **Gray Hat** | যারা **অনুমতি ছাড়াই** system-এ ঢোকে, কিন্তু **খারাপ উদ্দেশ্য থাকে না**; দুর্বলতা পেলে মালিককে জানায় (কখনো টাকা চায়) | অনুমতি ছাড়া scan করে bug রিপোর্ট করা |

## তুলনামূলক পার্থক্য

| বিষয় | White Hat | Gray Hat | Black Hat |
|---|---|---|---|
| অনুমতি | ✅ আছে | ❌ নেই | ❌ নেই |
| উদ্দেশ্য | নিরাপত্তা | মিশ্র (কৌতূহল/সুনাম) | ক্ষতি/লাভ |
| আইনি অবস্থা | বৈধ | **অবৈধ** (উদ্দেশ্য ভালো হলেও) | অবৈধ |
| Bug পেলে | মালিককে জানায় | মালিককে জানায় (কখনো পুরস্কার চায়) | কাজে লাগায়/বিক্রি করে |

## অন্যান্য Hacker (MCQ-র জন্য)

| ধরন | পরিচয় |
|---|---|
| **Script Kiddie** | অন্যের তৈরি tool ব্যবহার করে, নিজে গভীরভাবে জানে না |
| **Hacktivist** | রাজনৈতিক/সামাজিক উদ্দেশ্যে hack করে (যেমন: Anonymous) |
| **Red Hat** | Black hat-দের বিরুদ্ধে আক্রমণাত্মকভাবে লড়ে |
| **Blue Hat** | বাইরে থেকে system test করে (প্রতিষ্ঠান ভাড়া করে) |
| **Green Hat** | নতুন শিক্ষানবিস hacker |
| **State-sponsored** | সরকারি পৃষ্ঠপোষকতায় গুপ্তচরবৃত্তি/সাইবার যুদ্ধ |

## Real Scenario
**একটি ব্যাংকের website:**
- **White Hat:** ব্যাংক একজন security expert-কে চুক্তিতে নিয়োগ দিল। সে SQL Injection-এর দুর্বলতা খুঁজে পেয়ে রিপোর্ট করল, ব্যাংক তা ঠিক করল।
- **Gray Hat:** অনুমতি ছাড়াই একজন ব্যক্তি দুর্বলতা খুঁজে পেয়ে ব্যাংককে ইমেইল করে জানাল। উদ্দেশ্য ভালো হলেও কাজটি **অবৈধ**।
- **Black Hat:** একজন একই দুর্বলতা কাজে লাগিয়ে customer-এর data চুরি করে dark web-এ বিক্রি করল।

## Laravel Reference
```bash
composer audit      # dependency-তে জানা vulnerability খোঁজা (white hat-এর মতো নিজের app test)
```
আপনি নিজের Laravel app-এ `composer audit` চালিয়ে দুর্বলতা খুঁজলে সেটা **ethical practice**। অন্যের app-এ অনুমতি ছাড়া scan করলে সেটা **Gray/Black hat** কাজ।

## 📌 মনে রাখার মতো তথ্য
- **White Hat = Ethical Hacker**, অনুমতি আছে, বৈধ।
- **Gray Hat = অনুমতি নেই, কিন্তু খারাপ উদ্দেশ্য নেই**, তাও আইনত অপরাধ।
- **Black Hat = Cracker**, অবৈধ ও ক্ষতিকর উদ্দেশ্যে।
- **Hacker ≠ Cracker:** মূল অর্থে Hacker মানে দক্ষ প্রযুক্তিবিদ, আর খারাপ উদ্দেশ্যে ভাঙে যে সে **Cracker**।
- **Bug Bounty:** দুর্বলতা খুঁজে দিলে প্রতিষ্ঠান পুরস্কার দেয় (Google, Facebook ইত্যাদি)।
- **Penetration Testing (Pen Test)** হলো White hat-এর প্রধান কাজ।
- **Responsible Disclosure:** দুর্বলতা প্রকাশ্যে আনার আগে মালিককে জানিয়ে ঠিক করার সময় দেওয়া।
- নামের উৎস: পুরনো পশ্চিমা সিনেমায় ভালো চরিত্র **সাদা টুপি**, খারাপ চরিত্র **কালো টুপি** পরত।

## 🎯 পরীক্ষার টিপস
- Written-এ **তিনটির সংজ্ঞা → তুলনার table → scenario** দিলেই পূর্ণ নম্বর পাওয়া যায়।
- Gray Hat-এর ক্ষেত্রে লিখুন: *"উদ্দেশ্য ভালো হলেও অনুমতি ছাড়া ঢোকা অবৈধ।"* এটাই সবচেয়ে বেশি জিজ্ঞাসিত পয়েন্ট।
- MCQ-তে "কোনটি অনুমতি নিয়ে hack করে?" এলে উত্তর **White Hat**; "অনুমতি ছাড়া কিন্তু ক্ষতির উদ্দেশ্য নেই" এলে **Gray Hat**।

# 06. What is Cryptography? Distinguish between Symmetric (Secret Key) and Asymmetric (Public Key) Encryption with examples. Discuss cryptographic strength, ciphers, and how Public Key Encryption ensures Data Confidentiality, Integrity, and Authenticity. 


# 📘 Handnote: Cryptography, Symmetric vs Asymmetric Encryption

## ১. Cryptography কী?

**সংজ্ঞা:** Cryptography হলো তথ্যকে গোপন ও নিরাপদ রাখার বিজ্ঞান। এতে **Plaintext**-কে অর্থহীন **Ciphertext**-এ রূপান্তর করা হয় (Encryption), এবং শুধু বৈধ ব্যক্তি আবার আসল রূপে ফেরত আনতে পারে (Decryption)।

```
Plaintext ──[Encryption + Key]──► Ciphertext ──[Decryption + Key]──► Plaintext
 "HELLO"         (Cipher)           "KHOOR"                          "HELLO"
```

| Term | মানে |
|---|---|
| **Plaintext** | আসল পাঠযোগ্য বার্তা |
| **Ciphertext** | Encrypt করা অপাঠ্য বার্তা |
| **Key** | Encrypt/Decrypt করার গোপন মান |
| **Cipher** | Encryption-এর algorithm |

**Cryptography-র লক্ষ্য:** Confidentiality, Integrity, Authentication, Non-repudiation।

---

## ২. Symmetric vs Asymmetric Encryption

```
SYMMETRIC (একই Key)                 ASYMMETRIC (Key জোড়া)
Sender ─[Key K]─► Receiver          Sender ─[Receiver-এর Public Key]─► Receiver
        একই K দিয়ে decrypt                  Receiver-এর Private Key দিয়ে decrypt
```

| বিষয় | Symmetric (Secret Key) | Asymmetric (Public Key) |
|---|---|---|
| **Key সংখ্যা** | **একটি** (shared key) | **দুটি** (Public + Private) |
| **গতি** | **দ্রুত** | ধীর (গাণিতিক জটিলতা বেশি) |
| **Key distribution** | **সমস্যা**, key নিরাপদে পাঠানো কঠিন | সহজ, Public key সবাইকে দেওয়া যায় |
| **n জন user-এর key** | n(n−1)/2 টি | 2n টি |
| **ব্যবহার** | বড় data encrypt করা | Key বিনিময়, Digital Signature |
| **Authentication / Non-repudiation** | দেয় না | দেয় (Digital Signature দিয়ে) |
| **Key length** | ছোট (AES: 128/192/256 bit) | বড় (RSA: 2048+ bit) |
| **উদাহরণ** | **AES, DES, 3DES, Blowfish, RC4** | **RSA, ECC, Diffie-Hellman, DSA, ElGamal** |

> **Hybrid ব্যবস্থা:** বাস্তবে (যেমন HTTPS/TLS-এ) Asymmetric দিয়ে **session key** বিনিময় হয়, তারপর সেই key দিয়ে Symmetric encryption-এ দ্রুত data পাঠানো হয়।

---

## ৩. Cipher (সাইফার)

**Cipher** হলো encryption/decryption-এর algorithm।

```
                    Ciphers
          ┌───────────┴────────────┐
      Classical                  Modern
    ┌─────┴──────┐           ┌─────┴──────┐
Substitution  Transposition  Block      Stream
 (Caesar,      (Rail Fence)  (AES, DES) (RC4,
  Vigenère)                              ChaCha20)
```

| ধরন | কাজ | উদাহরণ |
|---|---|---|
| **Substitution** | অক্ষরের জায়গায় অন্য অক্ষর বসানো | **Caesar Cipher** (shift 3: HELLO → KHOOR) |
| **Transposition** | অক্ষরের **অবস্থান** বদলানো | Rail Fence |
| **Block Cipher** | নির্দিষ্ট আকারের block-এ data encrypt | AES (128-bit block), DES (64-bit block) |
| **Stream Cipher** | bit/byte ধরে ধরে encrypt | RC4, ChaCha20 |

---

## ৪. Cryptographic Strength (শক্তি)

Cryptographic strength হলো একটি encryption কতটা আক্রমণ প্রতিরোধ করতে পারে তার মাপ।

| নির্ধারক | ব্যাখ্যা |
|---|---|
| **Key length** | Key যত বড়, brute-force তত কঠিন (n bit হলে 2ⁿ সম্ভাবনা) |
| **Algorithm-এর নকশা** | Cryptanalysis (বিশ্লেষণ) প্রতিরোধের ক্ষমতা |
| **Key-র randomness** | অনুমানযোগ্য key দুর্বল |
| **Key গোপনীয়তা** | **Kerckhoffs's Principle:** Algorithm জানা থাকলেও শুধু key গোপন থাকলে system নিরাপদ থাকবে |
| **Work factor** | ভাঙতে কত সময়/শক্তি লাগে |

**উদাহরণ:** DES-এর key মাত্র **56 bit** বলে এখন ভাঙা সম্ভব (অনিরাপদ)। **AES-128** ভাঙতে 2¹²⁸ চেষ্টা লাগে, যা বাস্তবে অসম্ভব।

**সমতুল্য শক্তি:** RSA 3072 bit ≈ ECC 256 bit ≈ AES 128 bit। অর্থাৎ ECC ছোট key-তেই একই নিরাপত্তা দেয়।

## ৫. Public Key Encryption কীভাবে Confidentiality, Integrity ও Authenticity নিশ্চিত করে

### (ক) Confidentiality: Receiver-এর Public Key দিয়ে encrypt

```
Sender ──► Encrypt (Receiver-এর PUBLIC key) ──► Ciphertext ──► Decrypt (Receiver-এর PRIVATE key) ──► Receiver
```
শুধু Receiver-এর **Private key** আছে, তাই অন্য কেউ পড়তে পারে না।

### (খ) Integrity ও Authenticity: Sender-এর Private Key দিয়ে Signature

```
Message ──► Hash (SHA-256) ──► Digest ──► Encrypt (Sender-এর PRIVATE key) ──► Digital Signature
                                                          │
Receiver: Signature ──► Decrypt (Sender-এর PUBLIC key) ──► Digest-1
          Message   ──► Hash                              ──► Digest-2
          Digest-1 = Digest-2 ?  ✅ মিললে Integrity ও Authenticity নিশ্চিত
```

| লক্ষ্য | কীভাবে নিশ্চিত হয় |
|---|---|
| **Confidentiality** | Receiver-এর Public key দিয়ে encrypt, শুধু তার Private key-তে খোলে |
| **Integrity** | Hash মিলে গেলে বোঝা যায় message বদলায়নি |
| **Authenticity** | Sender-এর Public key-তে signature খুললে প্রমাণ হয় সে-ই পাঠিয়েছে (তার Private key ছাড়া signature সম্ভব নয়) |
| **Non-repudiation** | Sender পরে অস্বীকার করতে পারে না |

> তিনটি একসাথে পেতে: প্রথমে **Sender-এর Private key দিয়ে sign**, তারপর **Receiver-এর Public key দিয়ে encrypt**।

## Real Scenario
**ব্যাংক অফিসার Rahim, Head Office-এ গোপন loan রিপোর্ট পাঠাচ্ছে:**
1. রিপোর্ট Head Office-এর **Public key** দিয়ে encrypt করল, তাই পথে কেউ পড়তে পারবে না (Confidentiality)।
2. রিপোর্টের hash নিজের **Private key** দিয়ে sign করল, তাই Head Office নিশ্চিত হবে এটা Rahim-ই পাঠিয়েছে (Authenticity) এবং পথে বদলায়নি (Integrity)।
3. Rahim পরে বলতে পারবে না "আমি পাঠাইনি" (Non-repudiation)।

## Laravel Reference
```php
// Symmetric (AES-256, APP_KEY দিয়ে)
$enc = Crypt::encryptString('secret');
$dec = Crypt::decryptString($enc);

// Asymmetric (PHP OpenSSL)
openssl_public_encrypt($data, $encrypted, $publicKey);   // Confidentiality
openssl_private_decrypt($encrypted, $plain, $privateKey);
openssl_sign($data, $signature, $privateKey, OPENSSL_ALGO_SHA256);  // Signature
openssl_verify($data, $signature, $publicKey, OPENSSL_ALGO_SHA256); // Verify
```

## 📌 মনে রাখার মতো তথ্য
- **Symmetric = এক key, দ্রুত; Asymmetric = দুই key, ধীর।**
- Symmetric-এর মূল সমস্যা: **Key Distribution**। Asymmetric এই সমস্যার সমাধান।
- **Encrypt করতে Receiver-এর Public key, Sign করতে Sender-এর Private key।**
- **AES** = বর্তমান standard (128/192/256 bit, block size 128 bit); **DES** = 56-bit key, 64-bit block, এখন অনিরাপদ।
- **RSA** = Rivest, Shamir, Adleman, এর নিরাপত্তা বড় সংখ্যার **prime factorization** কঠিন হওয়ার ওপর নির্ভরশীল।
- **Diffie-Hellman** শুধু **key exchange** করে, সরাসরি data encrypt করে না।
- **Caesar Cipher** হলো সবচেয়ে সহজ substitution cipher।
- Cryptography ও **Steganography** আলাদা: Steganography-তে বার্তার **অস্তিত্বই লুকানো** হয়।
- **Kerckhoffs's Principle:** নিরাপত্তা নির্ভর করবে শুধু **key-র গোপনীয়তার** ওপর।

## 🎯 পরীক্ষার টিপস
- Written-এ ক্রম: **সংজ্ঞা → তুলনার table → Cipher ও Strength → Public Key দিয়ে C-I-A (দুটো diagram) → উদাহরণ**।
- "কোন key দিয়ে encrypt/sign" এই ফাঁদে অনেকে ভুল করে। মনে রাখুন: **গোপনীয়তার জন্য Receiver-এর Public, পরিচয়ের জন্য Sender-এর Private**।
- MCQ-তে সবচেয়ে বেশি আসে: Symmetric-এর উদাহরণ (AES/DES), Asymmetric-এর উদাহরণ (RSA), এবং "কোনটি দ্রুত?" (Symmetric)।
